# 07 — webOS 5 performance

## 1. Why this matters

webOS 5 uses an older Chromium engine and limited memory. A launcher that looks
good on a desktop browser can stutter on the TV if it uses modern CSS effects or
too many live DOM updates.

The UI was tuned for the TV first, not for the desktop.

## 2. Rules used in this project

### No live blur

Do **not** use:

- `backdrop-filter`;
- `filter: blur()` on full-screen layers;
- translucent panels with a blurred background;
- animated shadows that force a repaint.

Instead, use:

- opaque panels;
- precomputed gradients;
- static borders;
- a flat focus ring with `box-shadow: inset`;
- `transform` and `opacity` for animation.

### Avoid unsupported or expensive layout

On webOS 5, prefer:

- explicit widths/heights;
- `position: absolute` for fixed layout areas;
- `margin` instead of flex `gap` when in doubt;
- `top/right/bottom/left` instead of `inset`;
- simple grid/flex layouts.

### Pre-render panels

The Antena TV panel is built once and reused. Channel cards are not recreated on
every focus move. Focus changes only toggle classes.

### Limit live DOM work

- The clock updates once per minute, not every frame.
- The wallpaper changes only when the time slot changes.
- The train runs only when activated.
- HA states are refreshed on demand, not by a permanent poll.
- The app catalog is static until `sync-apps.ps1` regenerates it.

### Cache

- The channel list is cached in `localStorage`.
- Wallpaper images are local and preloaded.
- App icons are local files generated by `sync-apps.ps1`.

### Relaunch behavior

`handlesRelaunch: false` lets Home bring the existing app to the foreground
instead of creating a new instance. This avoids a full reload every time the
user presses Home.

## 3. CSS guidelines

Good:

```css
.card {
  background: #171b21;
  border: 1px solid rgba(255,255,255,.12);
}

.card.focused {
  box-shadow: inset 0 0 0 2px #fff;
  transform: scale(1.04);
}
```

Avoid:

```css
/* Do not use on webOS 5 */
.panel {
  backdrop-filter: blur(24px);
  filter: blur(8px);
}
```

Avoid animating:

- `box-shadow` with a large blur;
- `width`, `height`, `top`, `left`;
- `background-position` on large images;
- `filter` on a full-screen element.

## 4. Animation

- Use `transform: translate/scale` and `opacity`.
- Keep transitions short (120–220 ms for focus, around 1600 ms for wallpaper
  crossfade).
- Use `requestAnimationFrame` for movement that must follow the remote.
- Do not start a new animation on every key repeat without throttling.

## 5. Memory

- Keep wallpapers at 1920×1080 or similar; do not ship 4K photos.
- Do not include unused fonts or icon sets.
- Do not keep large base64 images in JS.
- Keep the HA entity list short.
- Remove test/debug DOM nodes before packaging.

## 6. Verification

On the TV:

1. Press Home repeatedly and check that Inicio appears without a flash.
2. Move across the whole grid with the arrow keys.
3. Open/close Antena TV, Casa, Inputs, Network and Settings.
4. Trigger the train and wait for it to end.
5. Change the TV time slot or edit the schedule to test the wallpaper.
6. Reboot and repeat.

Useful checks:

```bash
ssh root@TV_HOST \
  "luna-send -n 1 -f luna://com.webos.applicationManager/getForegroundAppInfo '{}'"
```

If the UI stutters, remove effects before adding new ones. On webOS 5, a simple
opaque panel is usually faster and looks better than a blurred one.

## 7. What not to do

- Do not add React/Vue or a large runtime for this UI.
- Do not use a remote web font.
- Do not load images from the network at startup.
- Do not run a permanent interval that re-renders the grid.
- Do not use `backdrop-filter` “just for the glass look”.
- Do not assume desktop Chrome behavior matches the TV WebView.
